# 06 · 右侧导航要求

本文档是 Codex 交接资料的一部分，记录此前已确认、但当前页面中出现回归缺失的**右侧 Part 导航**要求。

---

## 1. 这是一个明确的既定功能，不是可选装饰

网站是长页面数字教材。一个 Part 内固定包含：

1. Vocabulary
2. Scenes
3. Expressions
4. Don't Mix These Up
5. Useful Lines
6. Practice

用户此前已经指出：六个长模块连续铺在一页时，学习者很容易失去当前位置，因此需要长页面的模块定位导航。

当前右侧 Part 导航消失，属于**功能回归**，不是新的设计需求。

---

## 2. 不要混淆三种导航

项目中有三类不同导航，它们职责不同，都不能互相替代。

### A. 课程层级导航

用于：

**Chapter → Unit → Part**

当前主要由左侧 Sidebar / 移动端抽屉承担。

### B. Part 内模块导航

用于当前 Part 的六个教学模块：

- Vocabulary
- Scenes
- Expressions
- Don't Mix These Up
- Useful Lines
- Practice

**桌面端要求以右侧浮动导航存在。**

这是本文档讨论的功能。

### C. 页面顶部 / 底部快捷按钮

当前 `index.html` 还有页面右缘的：

- ↑ 顶部
- ↓ 底部

这两个按钮只用于快速滚动，不等于 Part 内模块导航，也不能用它们替代右侧模块导航。

---

## 3. 桌面端要求

桌面端右侧应保留一个紧凑、清楚、固定/浮动的 Part 内导航，让用户在长页面滚动时始终可以快速跳到六个模块。

应至少包含：

- Vocabulary
- Scenes
- Expressions
- Don't Mix These Up
- Useful Lines
- Practice

要求：

- 不遮挡正文；
- 不和页面顶部/底部按钮冲突；
- 点击后跳到对应 section；
- 视觉上是辅助导航，不抢正文注意力；
- 在正常桌面宽度下常驻可用；
- 保持现有六模块顺序，不重新定义课程结构。

如果当前代码中曾经有 floating part nav，应优先恢复/重构该逻辑，而不是重新发明另一套导航体系。

---

## 4. 手机端要求

移动端是手机优先设计，但**不要把六个长模块名挤成一条右侧浮动导航**。

已确认的移动端方向：

- Chapter / Unit / Part 使用可展开的三级目录 / 抽屉式目录；
- 当前 Part 需要保留“本课目录”或等价的紧凑入口；
- 点击后可以跳到 Vocabulary / Scenes / Expressions / Don't Mix These Up / Useful Lines / Practice；
- 触控区域应足够大，目标至少约 44px；
- 返回课程内容后应尽量保持阅读位置，不要因为打开目录而把用户强制带回页面顶部。

---

## 5. 与现有 `part-jump` 的关系

`app.js` 当前会在正文上方生成 `part-jump`，其中已经有六个模块 anchor。

这说明模块 ID 和基本跳转结构已经存在：

- `#vocabulary`
- `#scenes`
- `#expressions`
- `#comparisons`
- `#useful-lines`
- `#practice`

右侧导航不应重新创建另一组不同的 section ID。

推荐：

- 复用同一组 section 元数据和 anchor；
- 桌面端把相同数据渲染成右侧浮动 Part nav；
- 移动端使用紧凑目录入口；
- 避免 `part-jump`、右侧 nav、移动端 nav 各维护一套不同名称和链接。

---

## 6. 当前问题

用户在 2026-09-11 最新检查时发现：

**网站右侧的 Part 导航已经不见了。**

这很可能是在前几轮增强脚本、图片修复和入口脚本整理过程中被遗漏或停止加载。

Codex 需要审计：

- 历史 `lesson-enhancements.js` 是否包含 floating Part nav；
- 当前 `index.html` 是否已经停止加载承载该功能的脚本 / CSS；
- `site-v2.js` 是否没有迁移这部分功能；
- `styles.css` / `lesson-enhancements.css` 中是否仍存在相关样式；
- 恢复导航时是否会和 `.page-edge-nav` 顶部/底部按钮发生空间冲突。

---

## 7. 修复原则

右侧导航修复应当遵守：

1. **恢复功能，不重构课程结构。**
2. 复用 `sectionMeta` / 现有 section IDs，避免重复数据源。
3. 尽量把导航作为正式页面功能放进主代码，而不是再新增一个临时 hotfix。
4. 不因修右侧导航改动已经正常的 Adam Stone 音频。
5. 不因修右侧导航处理当前错误 SVG 图片资产；图片和导航可以在同一重构中协调，但验收应分开。
6. 桌面端与移动端采用不同呈现方式，不强行完全一致。

---

## 8. 验收标准

### 桌面端

- 右侧 Part 导航重新出现；
- 六个模块全部存在且顺序正确；
- 每项点击能准确跳转；
- 不遮挡课程内容；
- 不覆盖顶部/底部快捷按钮；
- 页面滚动时仍方便访问。

### 手机端

- 不出现拥挤的六项右侧浮栏；
- 有清晰的“本课目录”/等价入口；
- 可以访问同样六个模块；
- 打开/关闭目录操作方便；
- 正文阅读宽度不被导航压缩。

### 回归

- Chapter / Unit / Part Sidebar 仍正常；
- 顶部/底部按钮仍正常；
- Search 正常；
- 六个课程模块完整；
- Adam Stone 音频不受影响。

---

## 9. Codex 执行时的优先级

当前总体 P0 仍然是清理图片系统；但右侧导航缺失已经确认是一个独立回归问题，必须进入本轮交接范围，不能在图片修完后被遗忘。

推荐 Codex 在审计页面增强脚本时**同时确认右侧导航为什么消失**，然后：

- 图片链路和右侧导航分别设计修复；
- 分别验收；
- 避免再次出现“修 A 坏 B”。
