# 05 · 存在的问题

本文档记录当前项目已知问题。重点是让 Codex 明确：哪些问题是真实存在的、哪些已经解决、哪些方案已经被用户否定。

---

## 1. 当前最高优先级：图片系统不稳定

用户最近实际看到的问题包括：

- 第一张图只显示编号，没有底图；
- 一度只有第一张图位置，其他 Scene 图消失；
- 早期版本出现第二、第四张能显示，但第一、第三张不显示；
- 有些版本图片明显模糊；
- 旧大图不显示但继续占据空白位置；
- 多次修复后页面行为不一致。

这说明问题不只是“单个图片路径写错”，而是：

- 资源质量；
- 图片格式 / 编码；
- 缓存；
- 多代脚本注入；
- DOM 清理逻辑；
- 旧资源残留

共同造成的。

---

## 2. 当前视觉错误：极简 SVG 已被用户明确拒绝

当前仓库新增了：

- `hero-final.svg`
- `alarm-final.svg`
- `overslept-final.svg`
- `puffy-final.svg`

这些图采用极简扁平矢量风格。

用户明确表示它们与原来的目标视觉相差巨大，并再次提供了原始风格参考：精致、明亮、半写实动漫 / cinematic anime、人物和卧室环境都有细节。

因此：

**这些 SVG 不是“可接受但需优化”的版本，而是错误方向，应废弃。**

---

## 3. 图片资源目录已混入多代失败文件

当前 `assets/chapter-1/unit-1/part-1/` 中存在：

- 旧 `.webp`
- `-v3.webp`
- `-hq.svg`
- `-final.svg`

文件过多会造成：

- 容易引用错版本；
- 浏览器缓存难以判断；
- 调试时不清楚哪张才是真正源图；
- 后续维护者容易误把失败资源当正式资产。

需要在新方案验证后做一次有计划的清理。

---

## 4. 图片代码职责分散

仓库中存在多代增强脚本：

- `lesson-enhancements.js`
- `lesson-teaching.js`
- `site-v2.js`
- `media-final.js`

当前 `index.html` 实际加载的是：

- `app.js`
- `site-v2.js`
- `media-final.js`

但旧文件仍存在。

当前风险：

- `site-v2.js` 仍包含一套 `MEDIA` 和 `mediaFigure()` 图片注入逻辑；
- `media-final.js` 又包含另一套 `MEDIA` 和 `build()` / `ensure()` 图片注入逻辑；
- `media-final.js` 会删除 `.v2-media:not(.stable-teaching-media)`，也就是说它实际上在主动覆盖 `site-v2.js` 创建的图片节点。

这是明显的重复职责和冲突来源。

---

## 5. 图片没有正式进入课程数据模型

目前图片是根据标题硬编码：

- Part title 判断；
- Scene title 字符串匹配；
- JS 内部维护 `MEDIA` map。

问题：

- 未来每个 Part 都需要改 JS；
- 标题变动会导致媒体失配；
- 内容数据和媒体数据分离；
- 不利于自动化生成更多课程。

建议把 media 配置正式加入 Part JSON。

---

## 6. 图片清晰度问题曾真实存在

用户反馈：

- 最初显示出的图片非常模糊；
- 后续版本虽然稍微好一点，仍明显不够清晰。

历史资源中有些 WebP 文件体积只有几 KB 到十几 KB，这与较大网页展示尺寸不匹配。

后续必须以实际像素和浏览器 naturalWidth 为准，而不是只看文件扩展名或 CSS 宽度。

---

## 7. 当前音频状态：已解决，不属于当前故障

历史上音频经历过：

1. HeyGen / Adam Stone；
2. 因外链播放问题临时改浏览器 speechSynthesis；
3. 用户反馈变成女声、AI 痕迹更重；
4. 已恢复 HeyGen Starfish / Adam Stone 男声。

用户最近明确说：

**“音频问题解决了。”**

因此当前图片修复不得再次改音频体系。

---

## 8. README 已过时

当前 README 仍描述旧的 `lessons/YYYY-MM-DD.json` 日更结构，而正式网站已经转向：

- `curriculum/index.json`
- Chapter → Unit → Part

README 后续应更新，但不是当前 P0。

---

## 9. 仓库仍保留旧 daily lessons 数据

`lessons/` 下仍有旧日更文件。

这些文件可能是历史内容，不一定要立即删除；但需要明确：

- 当前主课程导航来自 `curriculum/`；
- 不要误把 `lessons/` 当成当前页面的主数据来源。

---

## 10. 当前线上状态不能只靠代码推断

此前多次出现：

- 仓库代码看似正确；
- 但 GitHub Pages 实际显示与预期不同。

因此 Codex 修复后必须做实际浏览器验证，包括：

- Network；
- Console；
- 图片直接 URL；
- 页面截图；
- 手机 viewport。

不能以“commit 成功”代替产品验收。

---

## 11. 视觉基准曾在长对话中被错误遗失

这是重要的项目管理问题。

用户已经较早确定的视觉方向是高质量半写实动漫 / 电影感场景，但后续为了解决技术问题，错误地改成了扁平 SVG。

因此后续应：

- 把视觉规范写入仓库（本次文档已经补上）；
- 不再依赖聊天上下文记忆；
- Codex 开始工作前先读文档。

---

## 12. 目前不建议同时做的事情

在图片恢复正常前，不要同时：

- 重做页面整体视觉；
- 改课程文案；
- 换 TTS；
- 改导航架构；
- 清空历史文件；
- 批量扩展 Chapter 2+。

先把 Part 1 作为稳定模板修好，再扩展。
