# 03 · 做法与经验

> 状态说明（2026-09-12）：本文保留修复前的需求与问题快照。图片与目录已修复上线，另增加音标和词汇一键展开。当前实现、剩余限制和发布证据见 [HANDOFF](HANDOFF.md) 及 07–09；不要把下文历史故障当作尚未解决的现状。

本文档记录这个项目已经尝试过的实现方法、哪些有效、哪些失败，以及后续开发应避免重复踩坑的地方。

---

## 1. 课程数据和页面渲染：当前主干思路是对的

### 当前做法

- 用 `curriculum/index.json` 管理 Chapter / Unit / Part 导航；
- 每个 Part 用独立 JSON 保存教学内容；
- `app.js` 负责加载 JSON、渲染页面、搜索、导航和基础交互；
- 音频元数据与正文 JSON 分离。

### 评价

这一架构适合继续扩展。

优点：

- 内容和页面逻辑分离；
- 未来可批量增加 Part；
- 适合自动化生成课程；
- 不需要每个 Part 单独写 HTML。

### 建议

继续把新增的媒体信息也数据化，而不是不断增加一次性 DOM 补丁。

---

## 2. Vocabulary 音频：长音频 + 时间戳切片是有效做法

### 当前做法

`part-1-audio.json` 保存：

- `voice`
- `locale`
- `audioUrl`
- 每个词条的 `start` / `end`

`app.js` 使用一个 `Audio()` 对象，按时间戳播放对应片段。

### 已验证结果

- 节省大量独立音频文件；
- 点读体验可接受；
- Adam Stone 男声和美音方向符合要求。

### 经验

这个方案比浏览器 `speechSynthesis` 稳定，也更能保持全站声音一致。

---

## 3. Scene 音频：外部 HeyGen 音频可以工作，但要注意稳定性

曾出现过灰色 `<audio controls>`、无法播放的问题。

后来为了绕过外链问题，临时改成了浏览器自带 TTS，结果产生两个新问题：

- 用户设备实际播放成女声；
- AI / 系统朗读感明显加重；
- 与此前统一的 Adam Stone 男声不一致。

### 最终经验

**不要用浏览器 speechSynthesis 替代正式课程音频。**

当前已恢复为 HeyGen Starfish / Adam Stone，用户明确反馈音频问题已经解决。

后续如果要进一步提升稳定性，优先考虑：

- 把最终固定音频下载并托管在仓库 / 稳定静态资源中；
- 不要更换声音模型；
- 不要在修图片时动音频。

## 4. 图片第一版：DOM 注入 + WebP

### 做法

最初通过增强脚本：

- 根据 Part title 判断当前 Part；
- 在 header 中插入 hero；
- 根据 Scene title 匹配 3 张 Scene 图；
- 图片放在 `assets/chapter-1/unit-1/part-1/`；
- 页面上再叠加编号和图下注释。

### 结果

结构思路可行，但资源链路和补丁脚本不断叠加后变得不稳定。

用户实际遇到：

- 图片位置存在但图不显示；
- 只剩编号；
- 有些图显示、有些图不显示；
- 图像明显模糊；
- 旧的大图空白占位仍存在。

## 5. 图片故障处理中的错误经验

### 错误 1：反复换文件名但没有先确认底层资源质量

曾依次尝试：

- `.webp`
- `-v3.webp`
- `-hq.svg`
- `-final.svg`

这让仓库中积累了多代资源，但没有建立一个单一可信源。

### 错误 2：同时存在多套图片增强脚本

历史上存在 / 仍留在仓库中的相关文件包括：

- `lesson-enhancements.js`
- `lesson-teaching.js`
- `site-v2.js`
- `media-final.js`

即使 `index.html` 当前未加载所有旧脚本，这种演化方式仍造成了：

- 逻辑来源不清；
- 重复清理 DOM；
- 某个脚本删除另一个脚本生成节点的风险；
- 修复时很难判断线上到底执行哪套逻辑。

### 错误 3：为了解决“加载稳定”牺牲视觉风格

最后临时做了 `*-final.svg` 极简矢量图。

技术上它们更容易加载，但视觉上完全偏离产品方向：

- 扁平；
- 简笔；
- 缺少人物细节；
- 缺少空间、光影和电影感；
- 更像儿童启蒙图。

用户明确拒绝。

**这是最重要的失败经验：不能用降低产品品质的方式解决技术故障。**

## 6. 正确的图片实现原则

Codex 接手时建议遵循：

### 6.1 先验证源图，再写代码

对每张最终图片先验证：

- 文件真实存在；
- 浏览器可以直接打开；
- MIME 正确；
- 像素尺寸足够；
- 文件不是被截断的二进制；
- 清晰度符合实际展示尺寸；
- GitHub Pages 路径可访问。

不要先写 DOM 插入逻辑，再猜资源是否正常。

### 6.2 只保留一个图片渲染来源

建议把媒体配置放进课程数据：

```json
{
  "heroMedia": {
    "src": "...",
    "alt": "...",
    "markers": [...]
  },
  "scenes": [
    {
      "title": "The Alarm Goes Off",
      "media": {
        "src": "...",
        "markers": [...]
      }
    }
  ]
}
```

然后由 `app.js` 正式渲染。

不要再新建 `media-hotfix-2.js` 一类文件。

### 6.3 编号和文本分离是正确方向

保留：

- 图上仅 ①②③；
- HTML 图下注释；
- 音频按钮跟 HTML 文本绑定。

不要把所有文字烙在图片里。

### 6.4 图像清晰度要按 CSS 展示尺寸倒推

如果桌面端展示宽度约 560px：

- 普通屏至少准备 1120px 宽源图更稳；
- 1536px 级源图足够；
- 不应把 180px / 320px 的缩略图拉伸到 500px 以上。

### 6.5 不要用错误的 SVG 视觉替代原图

SVG 作为技术格式本身没有问题，但当前仓库的 `*-final.svg` 内容是低质量扁平重绘，不是用户要的画风。

如果未来确实使用 SVG，也必须是高质量、符合视觉基准的作品，而不是几何占位图。

## 7. 缓存处理经验

GitHub Pages 和浏览器缓存曾让调试结果混乱。

建议：

- 修改 JS / CSS 后用明确版本号；
- 图片最好使用稳定文件名 + 内容哈希 / 构建版本，而不是手动无限叠 `v2/v3/final`；
- 调试时直接访问资源 URL 验证；
- 再验证页面；
- 不要把“缓存没刷新”当成所有问题的默认解释。

---

## 8. 应避免的开发方式

后续不要：

- 为了修一个问题连续叠 4 个补丁；
- 未验证线上资源就声明“已经修好”；
- 改图片时同时改音频；
- 改音频时改声音模型；
- 把正式产品视觉换成低质量占位图；
- 保留多套互相重叠的 DOM 注入逻辑；
- 在没有视觉回归检查的情况下直接合入主分支。

---

## 9. 推荐的开发流程

1. 读取 HANDOFF 与 5 份子文档；
2. 建独立修复分支；
3. 先做代码 / 资源审计；
4. 找回或重新准备 4 张正确风格的高清源图；
5. 浏览器直接验证资源；
6. 重构为单一正式媒体渲染路径；
7. 本地测试桌面 + 手机；
8. 确认 Adam Stone 音频未回归；
9. 部署 Preview / Pages；
10. 再合并。

---

## 10. 当前最有价值的经验总结

- 课程结构基本正确；
- 音频方案已经基本正确；
- 图片教学交互思路正确；
- **失败的是图片资源管理和渲染实现方式，不是“图片教学”这个产品方向。**

Codex 应解决技术实现，不应重新发明产品方向。
